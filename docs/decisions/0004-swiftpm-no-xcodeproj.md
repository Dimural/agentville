# 0004: One SwiftPM package, no .xcodeproj
Status: Accepted
Date: 2026-10-01

## Context
The repo is optimized for agentic development. Xcode project files are large, merge-hostile and hard for agents to edit correctly. The brief suggested `/App`, `/Hook` and `/Tools` folders.

## Decision
A single `Package.swift` with targets `AgentvilleCore` (library), `agentville-hook`, `agentville-replay` and `Agentville` (the app executable), using standard `Sources/` and `Tests/` folders. The `.app` bundle (Info.plist with `LSUIElement`, Helpers/agentville-hook, icon, signing) is assembled by `scripts/bundle-app.sh` (M7).

## Consequences
- `swift build` / `swift test` work from the terminal with no IDE; Xcode can still open `Package.swift`.
- The brief's folder names map to: `/App` → `Sources/Agentville`, `/Hook` → `Sources/agentville-hook`, `/Tools` → `Sources/agentville-replay` + `Tools/scenarios`, `/Plugin` → `Plugin/agentville`.
- No asset catalogs: all art is procedural anyway; the app icon is generated by a script.
